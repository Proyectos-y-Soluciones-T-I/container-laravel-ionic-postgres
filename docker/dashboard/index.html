Cómo configurar el entorno

      


        

          
            
              1
              Clonar el repo y crear los archivos .env
            
            
          
          

            
git clone <repo-url>
cd container-laravel-ionic-postgres
cp .env.example .env
cp envs/ayudando.env.example     envs/ayudando.env
cp envs/emergencias.env.example  envs/emergencias.env
cp envs/fiscalizacion.env.example envs/fiscalizacion.env

            
Completá los valores obligatorios en cada archivo:

            
    
              
  • .env — POSTGRES_PASSWORD, PGADMIN_PASSWORD
    • 
              
  • envs/<proyecto>.env — APP_KEY, JWT_SECRET, credenciales SMTP
    • 
              
  • APP_KEY — generá con el paso 4 (antes de levantar el backend)
    • 
            

          

        


        

          
            
              2
              Levantar infraestructura compartida
            
            
          
          

            
Una sola vez. Incluye postgres, pgAdmin y este dashboard.

            
docker compose -f docker-compose.shared.yml up -d
docker compose -f docker-compose.shared.yml ps   # shared_postgres debe mostrar (healthy)

          

        


        

          
            
              3
              Levantar un proyecto específico
            
            
          
          

            
Solo uno a la vez. Levantá el shared primero.

            
docker compose -f docker-compose.ayudando.yml --project-name ayudando up -d
# ó
docker compose -f docker-compose.emergencias.yml --project-name emergencias up -d
# ó
docker compose -f docker-compose.fiscalizacion.yml --project-name fiscalizacion up -d

          

        


        

          
            
              4
              Generar APP_KEY e importar la base de datos
            
            
          
          

            
Generá la clave sin el contenedor corriendo, pegala en envs/ayudando.env y luego levantá:

            
docker run --rm php:8.1-fpm-alpine php -r "echo 'base64:'.base64_encode(random_bytes(32)).PHP_EOL;"
# → APP_KEY=base64:...  (pegar en envs/ayudando.env antes del up)

docker compose -f docker-compose.ayudando.yml --project-name ayudando up -d

# Importar dump existente:
docker exec -i shared_postgres pg_restore -U postgres -d ayudando --no-owner --no-acl < src/ayudando/ayudando.tar

          

        


        

          
            
              5
              Conectar pgAdmin al servidor de base de datos
            
            
          
          

            

              
Hostpostgres(nombre del servicio, NO localhost)

              
Port5432

              
Usernamepostgres

              
Maintenance DBpostgres

              
Passwordvalor de POSTGRES_PASSWORD

            

          

        


        

          
            
              !
              Problemas frecuentes
            
            
          
          

            

              
APP_KEY vacío o inválido

              
Generá la clave sin contenedor corriendo, pegala en envs/<proyecto>.env y recreá:

              
docker run --rm php:8.1-fpm-alpine php -r "echo 'base64:'.base64_encode(random_bytes(32)).PHP_EOL;"
docker compose -f docker-compose.<proyecto>.yml --project-name <proyecto> up -d --force-recreate backend

              
restart NO es suficiente — el env_file solo se recarga al recrear el contenedor.

            

            

              
exec format error en Mac/Linux

              
El entrypoint tiene CRLF (Windows). Corregir:

              
docker run --rm -v "$(pwd)/docker/php/entrypoint.sh:/f" alpine sed -i 's/\r//' /f

            

            

              
Backend no conecta a la DB

              
shared_postgres debe estar healthy. Causa más común: POSTGRES_PASSWORD vacío.

              
docker compose -f docker-compose.shared.yml ps

            

            

              
Conflicto de puertos

              
Sobreescribí en .env: AYUDANDO_NGINX_PORT=8083, AYUDANDO_FRONTEND_PORT=4203

            

            

              
Reset total de la DB

              
# ⚠️ Destruye todos los volúmenes
docker compose -f docker-compose.shared.yml down -v
docker compose -f docker-compose.shared.yml up -d
docker exec -i shared_postgres pg_restore -U postgres -d ayudando --no-owner --no-acl < src/ayudando/ayudando.tar
